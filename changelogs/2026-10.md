# October 2026

## 2026-10-22

- 3D graphs can use depth of field: the selected nodes stay sharp and the rest of the graph blurs with its distance from them, in front and behind, like a camera lens. The blur gets stronger as the camera moves closer to the selection and the selection stays sharp while you orbit or zoom. Turning it on or off, changing its strength and moving the focus to a new selection all animate with an easing you can choose, and reduced motion makes them jump. It is off by default; turn it on with `depthOfField: { enabled: true }` or `setDepthOfField()`. It does nothing in 2D and costs nothing while off ([#158](https://github.com/yggy-tech/graphraum/issues/158)).

## 2026-10-21

- `setData(data, { fit: false })` replaces the graph and keeps the camera where it is, so a host that sends a full snapshot on every change no longer resets the view. The default still fits the camera ([#150](https://github.com/yggy-tech/graphraum/issues/150)).

## 2026-10-19

- In 3D, edges and their arrowheads now end on a node's visible outline from every camera angle, so arrowheads show instead of hiding under the node they point at. The end is placed on screen, where the camera-facing node is, rather than one radius along the edge in space. This is exact for circle nodes; other shapes use their width as the radius. 2D is unchanged.

## 2026-10-11

- `flyTo({ nodeIds })` animates the camera to a group of nodes and resolves when it arrives, or `false` when someone interacts first. In 3D it keeps the current viewing angle, so a running auto-orbit carries on around the new spot, which makes ambient tours from cluster to cluster possible. It jumps instead of animating when reduced motion is on.

## 2026-10-10

- The docs site is simpler. It now has three parts: a home page, the docs (Start, Guide, Reference) and one playground. The playground replaces the Explorer, the Prove page and the three demo pages: it has the Knowledge, Software and Fraud scenes, a stress test up to 100,000 nodes, and Prove as a side panel that compares your device with the reference run. Old links redirect to the new pages.

## 2026-10-09

- `fitView` accepts `{ nodeIds }` to frame a subset of nodes, for example a highlighted path, in 2D and 3D.

## 2026-10-08

- `fitView()` in 2D now undoes wheel zoom, so fitting after zooming in or out frames the graph the same way as the first fit instead of keeping it small or cropped ([#130](https://github.com/yggy-tech/graphraum/issues/130)).
- Edges now always draw behind nodes in 3D, as they already did in 2D, so busy hubs keep a clean node face. In 3D a node behind an edge now shows on top of it, and overlapping edges no longer hide each other by depth ([#127](https://github.com/yggy-tech/graphraum/issues/127)).
- In 3D, edge ends now meet the outline of circle nodes from every camera angle instead of stopping short of it, including edges that point toward or away from the camera. For other shapes the ends land close to the outline but can stop slightly short of it on long or angular nodes, depending on the view. 2D is unchanged. An arrowhead on an edge that points almost straight at the camera can sit under its node ([#127](https://github.com/yggy-tech/graphraum/issues/127)).
- Fixed node, edge, marker, selection, and glow colors drawing darker than specified. A node set to `#8a9096` drew as `#41474e`; it now draws as `#8a9096`, the same as that color in CSS and as the canvas background ([#123](https://github.com/yggy-tech/graphraum/issues/123)).
- This changes how every graph looks: colors are noticeably lighter than in earlier versions, for both presets and for custom colors, and glow halos on dark backgrounds look brighter and wider because they blend over the corrected colors. The dark and light presets keep their values, because they now draw as their documented palette. If you picked colors to compensate for the darker output, set them back to the values you meant.
- `fitView()` in 3D now frames the graph to fit the canvas: the graph spans most of the canvas width or height instead of about a third, glow halos stay in view, and nodes no longer fall off the sides of tall canvases ([#124](https://github.com/yggy-tech/graphraum/issues/124)).

## 2026-10-07

- 3D graphs can slowly orbit on their own with `setAutoOrbit()`. The orbit is off by default, pauses while people interact and resumes after a short idle, and stops while the tab is hidden or the graph is off screen ([#113](https://github.com/yggy-tech/graphraum/issues/113)).
- Edges can be dimmed with `setEdgeState("dimmed", ids)`, styled by the new `dimmedEdge` and `dimmedEdgeOpacity` theme colors, so focusing a neighborhood recedes edges as well as nodes. Selected edges stay highlighted ([#116](https://github.com/yggy-tech/graphraum/issues/116)).
- Highlighting edges with `setEdgeSelection` on hover stays fast on large graphs: only the edges that changed are repainted.
- `setEdgeSelection` now ignores IDs that are not in the graph, and `setData` drops selected edges that no longer exist. The `selectedEdges` diagnostic counts only real edges, so it can be lower than before for hosts that pass stale IDs.
- `GraphraumTheme` has two new required fields, `dimmedEdge` and `dimmedEdgeOpacity`. Hosts that type a complete theme object must add them; partial themes and the presets need no change. A partial theme that sets `dimmedEdgeOpacity` to `undefined` or to a value outside 0 to 1 now throws.
- Fixed edges that could show outdated lines when a layout update and a pan or zoom landed in the same frame.
- Nodes can glow: set `glow` between 0 and 1 to draw a soft halo in the node's color around the few nodes you want to stand out ([#114](https://github.com/yggy-tech/graphraum/issues/114)).
- Live force layout can keep data-defined clusters together: pass cluster indices to `createForceSimulation()` and tune `clusterStrength`. Nodes added later join their cluster ([#115](https://github.com/yggy-tech/graphraum/issues/115)).
