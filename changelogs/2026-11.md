# November 2026

## 2026-11-10

- **Breaking:** the force layout moved to its own entry, `@yggy-tech/graphraum/layout`. Import `computeForcePositions`, `computeClusteredForcePositions`, `createForceSimulation`, `DEFAULT_FORCE_SETTINGS`, `FORCE_LAYOUT_STYLES`, `forceIterationCount` and the `Force*` types from there instead of `@yggy-tech/graphraum`. Apps that only render get a 5.7 KiB (gzip) smaller main bundle, and the main entry has room again for new features.
- A layout no longer starts over when a graph gains nodes. Pass the previous positions as `initialPositions` with `warmStart: true` to `computeForcePositions()` or `createForceSimulation()`, and use the new `placeNewNodes()` from `@yggy-tech/graphraum/layout-start` to put new nodes next to their neighbours (or their cluster): known nodes keep their place and the layout only settles briefly, so existing nodes barely move. It works with both layout styles, clusters and anchors. The Layout guide also explains when a layout computed on your server is the better choice ([#147](https://github.com/yggy-tech/graphraum/issues/147)).
- Small clusters now sit closer to the rest of a clustered layout. Before, a group of 2% of the nodes kept an empty margin 4 times (`"classic"`) to 12 times (`"edge-t"`) wider than a large group. Cluster centres are now spaced by cluster size, and `"edge-t"` scales the push between clusters by size. The margin is now 2.6 and 8.9 times wider, and groups stay as clean as before ([#192](https://github.com/yggy-tech/graphraum/issues/192)).

## 2026-11-07

- Added an optional focus lens. Turn it on with `focusLens: { enabled: true }` or `setFocusLens()` and nodes near the center of the canvas draw larger while nodes toward its edge draw smaller, in 2D and 3D. Labels from `GraphraumOverlay` fade in only on the large ones. Positions never move, picking follows the drawn size, and a hovered or selected node never shrinks. It is off by default.
- You can now change how a graph looks beyond colours. Pass `style` to the constructor or call `setStyle()` to set a default node stroke width, a default arrowhead size and label typography, and switch between ready-made looks without rebuilding the graph. `@yggy-tech/graphraum/styles` ships `neutral` (greys with blue accents for hover and selection, on a transparent canvas with a system font), `blueprint`, and `classicDark` and `classicLight`, which are exactly the looks graphraum has always had. Labels get `--graphraum-label-*` CSS custom properties you can use in your own label styles. The default look does not change, and drawing cost stays the same ([#203](https://github.com/yggy-tech/graphraum/issues/203)). See the new Styling guide.
- Nodes can show an icon. Build an atlas from SVG strings with `createIconAtlas()` from `@yggy-tech/graphraum/icons` (it includes a helper for raw Phosphor SVGs, and no icon set is bundled), pass it to `graph.setIconAtlas()`, and give nodes an `icon` index. Icons are tinted, sit inside the node in lit and toon shading and in 3D, and cost no extra draw call. The Data and visuals guide has a new Icons section ([#208](https://github.com/yggy-tech/graphraum/issues/208)).
- You can now check which groups in a drawing are real. `measureLayoutStability()`, imported from `@yggy-tech/graphraum/diagnostics` so it stays out of the main bundle, lays the graph out with several seeds and reports how stable each cluster is, next to the score of a shuffled copy of the graph that has the same node degrees but no real groups. A cluster is trustworthy when it scores clearly above that shuffled copy. The Prove run reports the score for its fixture ([#194](https://github.com/yggy-tech/graphraum/issues/194)).
- Long chains and strips no longer start knotted. Force layouts take an optional `initialPositions` start, and the new `@yggy-tech/graphraum/layout-start` entry computes one from graph distances, so the layout starts stretched along the graph's length. On a long grid strip the layout comes out with almost no folds where the default random start leaves dozens or hundreds. The default start is unchanged and the main bundle barely grows ([#193](https://github.com/yggy-tech/graphraum/issues/193)).
- Force layouts can follow positions you already have. Pass `anchors` to `createForceSimulation()` with one position per node, for example a PCA or UMAP projection of embeddings, and nodes start there and are pulled back towards it. The positions can use any range, nodes with `NaN` are laid out freely, and `settings.anchorStrength` sets how closely the layout follows them. The new Guided layout guide shows how to combine anchors, clusters, and weak neighbour edges ([#170](https://github.com/yggy-tech/graphraum/issues/170)).

## 2026-11-06

- Force layouts have a second style for graphs that end up as one tangled ball. Set `layoutStyle: "edge-t"` in `ForceSettings` to give well-connected nodes more room, so groups separate and hubs no longer pile up in the middle. It works for `computeForcePositions()`, clustered layouts and `createForceSimulation()`, and a running simulation can switch with `setSettings({ layoutStyle: "edge-t" })` without starting over. Its one-shot layout runs 8 times as many steps, so run large graphs in a worker. `"classic"` stays the default ([#191](https://github.com/yggy-tech/graphraum/issues/191)).
