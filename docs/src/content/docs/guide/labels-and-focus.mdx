## Labels and a focused toolbar

`createOverlay()` projects a bounded set of host-created HTML elements over the canvas. It is the same dense-canvas plus sparse-DOM split used by graph editors: WebGL remains responsible for the graph, while your application owns rich text, CSS, buttons, and action handling. The two-draw-call GPU path is unchanged: labels stay in the DOM overlay. The [playground](../../playground/?scene=stress) turns this on for the stress scene: focus labels, an Inspect toolbar, and one HTML card.

Pointer move updates hovered node state automatically. Use `getNeighborIds(id)` for 1-hop adjacency when building focus chrome outside the overlay.

### Label policies

`labelPolicy` controls which titles appear:

| Policy | Behavior |
| --- | --- |
| `manual` (default) | Host calls `setLabels(ids)` |
| `auto` | Budget by importance among visible nodes (`autoLabels: true` maps here) |
| `focus` | Prefer selected ∪ hovered ∪ 1-hop neighbors, then fill by importance within `maxLabels` |

```ts
const overlay = graph.createOverlay({
  labelPolicy: "focus",
  autoToolbar: "selected",
  maxLabels: 24,
  renderLabel: ({ id, presentation }) => {
    const label = document.createElement("span");
    label.className = "my-graph-label";
    label.textContent = presentation?.title ?? id;
    return label;
  },
  renderToolbar: ({ id, presentation }) => {
    if (!presentation) return null;
    const toolbar = document.createElement("div");
    for (const action of presentation.actions) {
      const button = document.createElement("button");
      button.textContent = action.label;
      button.disabled = action.disabled ?? false;
      button.onclick = () => runNodeAction(id, action.id);
      toolbar.append(button);
    }
    return toolbar;
  },
});
```

`autoToolbar: "selected" | "hovered"` keeps the toolbar pinned without calling `setToolbar`. With `"hovered"`, selection is the fallback when nothing is hovered. When `autoToolbar` is off (default), call `overlay.setToolbar(nodeId)` yourself.

### Rich HTML focus cards

Dense nodes stay on the GPU. For a handful of selected or hovered nodes, `renderRichNode` projects host HTML (any framework) under the node. This is the focus tier in the [fidelity-on-demand ADR](https://github.com/yggy-tech/graphraum/blob/main/docs/adrs/adr-fidelity-on-demand.md).

```ts
const overlay = graph.createOverlay({
  autoRichNodes: "selected",
  maxRichNodes: 4,
  renderRichNode: ({ id, presentation }) => {
    const card = document.createElement("article");
    card.textContent = presentation?.title ?? id;
    return card;
  },
});
```

`autoRichNodes` is `"selected"`, `"hovered"`, or `"focus"` (selected then hovered, no neighbors). It slices to `maxRichNodes`. Manual `setRichNodes(ids)` throws when the list is longer than the cap. Rich HTML edges are not in this API.

Off-screen nodes stay out of budgeted sets. Manual `setLabels()` still works under `auto` / `focus` until the next view or focus change overwrites the list. Export `selectBudgetedLabelIds`, `selectFocusLabelIds`, `orderFocusNodeIds`, `boundOverlayIds`, and `selectRichNodeIds` for the same policies outside the overlay.

### Manual labels

```ts
const overlay = graph.createOverlay({
  renderLabel: ({ id, presentation }) => {
    const label = document.createElement("span");
    label.textContent = presentation?.title ?? id;
    return label;
  },
});
overlay.setLabels(["person:ada", "place:london"]);
overlay.setToolbar("person:ada");
```

`setLabels()` still throws when the list exceeds `maxLabels`. Off-screen and missing nodes are safely hidden or ignored. Call `destroy()` with the graph lifecycle.

## Focus lens

The focus lens draws nodes near the center of the canvas larger and nodes toward its edge smaller, like the app grid on a watch. It works in 2D and 3D, and only drawn size changes: positions, edges and the camera stay as they are. It is off by default.

```ts
const graph = new Graphraum(container, { focusLens: { enabled: true } });

graph.setFocusLens({ centerScale: 2.5, reach: 0.4 }); // omitted fields keep their values
graph.setFocusLens({ enabled: false });
```

A node's size factor depends on its distance from the center of the canvas on screen, so in 3D it follows the camera, and the lighting and depth cues are untouched. The factor eases from `centerScale` (default `2`) at the center to `edgeScale` (default `0.75`) at `reach` (default `0.5`, a fraction of the shorter canvas side) and beyond. Each frame a node's size moves `easing` (default `0.35`) of the way to that target, so panning feels smooth; with `prefers-reduced-motion: reduce` it jumps to the target.

- Picking uses the size a node is drawn at.
- A hovered or selected node never draws smaller than its own size.
- Edges meet node centers while the lens is on, because the outline of a node changes every frame.
- In 2D, larger nodes draw on top of smaller ones.
- Aggregated density tiers draw at their own size.

`GraphraumOverlay` fades its labels with the lens: a label is transparent until the node's size factor passes `1 + (centerScale - 1) * labelThreshold` (default `0.45`) and fully opaque `(centerScale - 1) * labelRamp` (default `0.35`) above that, so only nodes near the center show a label. Hovered and selected nodes always show theirs. If you render your own labels, read `graph.getFocusLensLabelAlpha(nodeId)` from an `onViewChange` listener.

The size math is a pure function you can reuse or test on its own:

```ts
import { focusLens } from "@yggy-tech/graphraum";

focusLens(0, 800); // { scale: 2, labelAlpha: 1 }
focusLens(400, 800); // { scale: 0.75, labelAlpha: 0 }
focusLens(100, 400, { centerScale: 3, reach: 0.25 });
```

## Density policy

Color, shape, and size can remain visible across the graph. Titles use the budgeted overlay policy above (`autoLabels` or a host-owned `setLabels()` list). Full properties, actions, and rich HTML cards belong to a bounded focused or selected subset. This preserves both accessibility and the dense rendering path.

## Keep meaning outside color alone

The WebGL surface is not the accessibility tree. Applications should mirror focus and selection into an accessible node list, expose labels in HTML, and pair semantic colors with text, shape, or filtering controls. graphraum owns the fast visual primitive; the host owns understandable interaction.
